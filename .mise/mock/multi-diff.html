Combined diff: Open Cluster Changes for "Settings panel"

Opened from the cluster row's action. This is VS Code's built-in multi-diff editor (vscode.changes). It lists one entry per cluster file that still needs review, each against its own base: the reviewed snapshot where one exists, the merge base otherwise. The right side is the working tree. Files are in the cluster's path order. Reviewed files with no changes since are not listed.

Notes
  • Tab title: "Cluster Changes: " plus the cluster label.
  • New title-bar button Mark Cluster Reviewed (dashed outline, first in the editor toolbar; tooltip shown above). It does what the sidebar's cluster Mark Reviewed does: snapshots every file in the cluster. Afterwards the tab stays open showing what was just reviewed, and the sidebar row updates to reviewed (6/6). The button shows only on Delta Review combined-diff tabs.
  • A fresh, never-reviewed cluster opens the same way, with every entry against the merge base (like validate.ts here).
  • The per-file "last reviewed ↔ working tree" / "merge base ↔ working tree" labels on the right of each header are aspirational. The multi-diff editor shows only the file name and folder, so they may not render. For a moved file, the left side is the old path's snapshot, which comes from task 1's inheritance.
  • If a file changed since review was then deleted, its entry shows the snapshot on the left and an empty right side, the same as the single-file "last reviewed ↔ deleted" diff.
  • Marking one file: the combined diff adds no per-file buttons; the file headers carry only the editor's own actions. To mark a single file while the combined diff is open, use that file's existing Mark Reviewed button in the Delta Review sidebar. The only button this work adds to the diff is Mark Cluster Reviewed in the editor title bar.
