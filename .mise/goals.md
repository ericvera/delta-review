## Decisions

1. Reviewing the origin's deletion row does not cancel inheritance: the moved file keeps the snapshot it inherited, and the deletion row is reviewed independently.
2. Unmarking a moved file that inherits also clears the origin's key, so when the origin is its own deletion row that row is unmarked too. Accepted.
3. The combined cluster diff contains every file in the cluster that still needs review, each against its own base (its reviewed snapshot where one exists, the merge base otherwise), in VS Code's multi-diff editor. The button therefore shows on fresh, never-reviewed clusters too. (Supersedes the earlier changed-since-review-only choice.)
4. The combined diff offers a "Mark Cluster Reviewed" button in its editor title bar. Per-file mark buttons inside the combined diff are out of scope: verified that the file-header menu (`multiDiffEditor/resource/title`) is gated behind the proposed API `contribMultiDiffEditorMenus`, which a published extension cannot use.
5. Clicking into a file's text in the combined diff selects that file's row in the Delta Review pane (without moving keyboard focus), so its existing Mark Reviewed button is one click away. Clicking only a file's header does not select it (VS Code does not report it).

## Proposal

- Issue: declared whole-file moves fail to inherit review when extractions share the origin or the origin is still a deletion row; and post-review touch-ups in a cluster can only be read one file at a time.
- Approach: count only whole-file moves for the shared-origin check and let a deletion-only origin be inherited from (surviving a review of that deletion row); add an "Open Cluster Changes" cluster command that opens every needs-review file of the cluster in VS Code's multi-diff editor, each against its own base, with a "Mark Cluster Reviewed" title-bar button. Per-file buttons inside the diff are out (proposed API only); instead, clicking into a file's text there selects its row in the pane.
- Skips: none — spec and critic both run, since the work spans the review model, review state, a new command and docs.
